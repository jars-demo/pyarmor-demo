# AGENTS.md

Guidance for AI coding agents (Claude Code, Codex, Cursor, Copilot, Gemini CLI) and developers
working in this repo. Humans: start with [README.md](README.md).

## What this is

A hands-on workshop for protecting Python with [PyArmor](https://pyarmor.readthedocs.io/) 9.2.7: a
FastAPI backend whose business logic gets obfuscated, verified and shipped in Docker, a Next.js
website that teaches it (static on Vercel, or full with a live Lab via Docker), and 13 workshop
chapters. Attendees read the code as a reference, so prefer clear over clever. The project is
defensive and educational: never add arbitrary code execution, secrets, or claims that obfuscation
makes code secret.

## Commands

```bash
uv sync                                              # Python 3.12 + deps + PyArmor 9.2.7
uv run pytest                                        # 38 tests, original source
uv run ruff check . && uv run ruff format --check .
uv run python -m app                                 # API → :8300
uv run python scripts/obfuscate.py                   # → build/protected (fails on PyArmor errors)
uv run python scripts/verify.py --tests              # static checks + the same tests on the protected build
uv run python scripts/smoke.py --expect-build protected   # HTTP check of any running instance
uv run python scripts/gen_playground.py              # regenerate app/frontend/src/data/playground.json
cd app/frontend && npm ci && npm run dev             # site → :3300 (calls :8300; CORS allows it)
cd app/frontend && npm run lint && npm run typecheck && npm run build && npm run build:static
docker compose up -d --build --wait                  # api :8300 + web :3300, hardened
uv export --frozen --no-default-groups --no-emit-project --format requirements-txt -o requirements.txt
```

## Rules

1. **Verify every PyArmor command before documenting it.** Run it with the pinned version and
   paste the real output. Never use PyArmor 7 syntax (`pyarmor obfuscate`, `pyarmor pack`).
2. **Never trust PyArmor's exit code.** 9.2.7 exits 0 on `ERROR out of license`. Build steps go
   through `scripts/obfuscate.py`, and outputs through `scripts/verify.py`.
3. **Keep modules small.** The trial rejects "big" modules (a module of ~30 realistic functions
   passes; 200 tiny ones fail). Split before you hit it.
4. **Always exclude the frontend** from obfuscation: `--exclude app/frontend` (its `node_modules`
   can contain `.py` files). In `--pack` mode also exclude `.venv` and `.venv/*`.
5. **Same Python everywhere.** Protected builds only run on the Python minor version and platform
   that built them: both Dockerfile stages share one base image; CI uses 3.12.
6. **Behaviour is a contract.** Golden values live in `tests/test_business_logic.py`,
   `tests/test_api.py` and `scripts/smoke.py`. If the algorithm changes on purpose, update all
   three, the workshop's expected outputs (chapters 03, 05), and regenerate the Playground.
7. **Docs follow code.** A changed command, path, count or output means updated `workshop/*.md`;
   a new chapter also needs `src/lib/chapters.ts`. Root holds only `README.md` and `AGENTS.md`.
8. **Security language stays accurate.** Say "raises the effort", "reduces readability". Never
   "encrypted source", "impossible to reverse", "completely secure".
9. **Pins move together.** Python deps in `pyproject.toml` → `uv lock` → regenerate
   `requirements.txt` (CI diffs it). `PYARMOR_VERSION` in `app/backend/Dockerfile`, `pyproject.toml`
   and `src/lib/site.ts`. Exact versions in `package.json`. Actions pinned to commit SHAs.
10. **Never commit** `.env`, `build/`, `dist/`, `.pyarmor/`, `node_modules/`, `.next/`, `out/`,
    keys, or a PyArmor registration file.

## PyArmor licenses

The project uses the free trial and needs no secret. To use a paid license in CI, store the
registration file as a base64 GitHub secret (for example `PYARMOR_REGFILE_B64`), write it to a temp
file in the job, run `pyarmor reg <file>` before `scripts/obfuscate.py`, and delete it afterwards.
Never commit it, never print it. Read the [license terms](https://pyarmor.readthedocs.io/en/latest/licenses.html)
first: CI licenses send runner details to PyArmor's server and are rate-limited.

## Brand

White-first. PyArmor Blue `#2563EB` (hover `#3B82F6`), Ink `#0F172A`, muted `#64748B`, borders
`#E2E8F0`, page `#F8FAFC`, hero gradient `#EFF6FF → #FFFFFF`. Inter (H1 700, H2 650, H3 600, body
400, labels 500), JetBrains Mono for code. Tokens live in `src/app/globals.css`; use the token
classes (`bg-brand`, `text-accent`, `border-line`), never raw hex in components. Dark mode is
opt-in via the toggle. No heavy gradients, glassmorphism or decorative animation.

## Style

Python 3.10+ syntax, ruff (line length 100), type hints on public functions, stdlib-only scripts.
TypeScript strict, function components, oxlint. Every command in docs has **What it does / Why /
Expected**. Commits: Conventional Commits, `type(scope): Imperative summary`, with a body saying
why.

## Skills

This repo follows the [JARS Skills](https://github.com/jars-demo/jars-skills) playbooks
([skills.jishanahmed.in](https://skills.jishanahmed.in)). Use `env-setup` for first setup,
`write-tests` for new behaviour, `debug-session` for failures, `dependency-update` for bumps (one
dependency per change, regenerate `requirements.txt`), `code-review` before merging, `commit-style`
for commits, and `changelog` / `release` for `docs/CHANGELOG.md` and tags. Never push, tag or
publish unless asked.
